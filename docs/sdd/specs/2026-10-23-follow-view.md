# console-log — панель без вкладок, що йде за найновішою задачею й за агентом, відкритим унизу — design

**Date:** 2026-10-23
**Status:** agreed
**Prototype:** — (візуально лише прибирається рядок вкладок; поведінку перевіряємо наживо, див. §6)

## 1. Problem

Під промптом Claude Code (під modern-hud) уже є стандартний список запущених субагентів і фонових процесів: `● main`, `○ general-purpose …`, `↓ 2 more`. Панель console-log дублює його власним рядком вкладок `BACKGROUND` над output, зі своєю навігацією `ctrl+→`/`ctrl+←`, яку людина мусить вписати в `~/.claude/keybindings.json`.

Наслідки:
- два перемикачі одних і тих самих задач, і кожен показує своє;
- щоб побачити, що робить свіжий субагент, треба фокусувати панель і гортати вкладки;
- `✗`/`■` висять у рядку вкладок, поки їх не відкриєш і не покинеш, тож панель не закривається сама, навіть коли все скінчилось.

## 2. Constraint that shapes the solution

Перевірено в бандлі Claude Code 2.1.309:

- Перемикання в нижньому списку викликає внутрішній `JB(taskId)` → `viewingAgentTaskId` напряму. Хук `ui.view` при цьому **не** піднімається, тож мод не може ні перехопити перемикання, ні відхилити його.
- `$.ui.view({})` дозволено лише тоді, коли кореневою подією є `ui.press`, `ui.input` або `ui.select` елемента мода. Виклик із `ui.render` повертає `{ deny: "not person-initiated" }`. Тож повернути основне вікно на батьківську сесію після перемикання внизу мод не може.
- Єдине, що мод бачить: рушій перемальовує `Pane` з новим `e.props.view` (`SiteView`, `agentId` відкритого агента або нічого для `main`). Це стається лише тоді, коли панель відкрита.
- Вибір *процесу* (shell/Monitor) унизу відкриває діалог рушія. Моду про нього нічого не приходить.

Відкинуто:
- **Утримувати основне вікно на `main`.** Неможливо з причин вище.
- **Лишити власні вкладки для ручного вибору.** Користувач хоче один перемикач, той, що внизу.
- **Кнопка «← main» у панелі.** Два кроки замість одного; користувач обрав автономну панель.

## 3. Solution

### 3.1 Що показує панель

Одна чиста функція `pick(board, view)` у `hooks/tasks.ts` повертає задачу, яку показує панель:

1. `view` задано (унизу відкрито агента): задача з `id === view`. Якщо мод такого агента не відстежує (teammate, workflow, агент без вкладки), повертається синтетична `{ id: view, kind: 'agent', command: 'agent', label: 'agent', startedAt: 0 }`.
2. Інакше — працююча задача (`!status`) з найбільшим `startedAt`. При рівності виграє пізніша в масиві.
3. Інакше — завершена задача з найбільшим `endedAt`.
4. Інакше — `undefined`.

`Board` стає `{ tasks: ConsoleTask[] }`: поле `selected`, атом `selected`, `selectTask` і `ConsoleTask.viewed` прибираються. Новий атом `view` (`string | undefined`, ключ `view`) зберігає останній `e.props.view.agentId`, який бачив рендер.

### 3.2 Як мод дізнається про перемикання внизу

На початку `ui.render` для `Pane` хук порівнює `e.props.view.agentId` з атомом `view`. Якщо вони різні, він робить `update($, view, …)`, чистить `lines` і `readFailed` і запускає `void refresh($)`. Рендер при цьому не чекає. `load` читає `pick(board, view)`: агент → `$.session.messages({ agentId })`, процес → `tail` за `path`, як і зараз.

Поки панель закрита, перемикання внизу не видно. `/console-log` відкриває панель, і перший же рендер підхоплює `view`.

### 3.3 Життєвий цикл задач і закриття

- `ConsoleTask` отримує `endedAt?: number`. Його ставлять `applyNotification`, `syncAgents`, `expireTasks` і `stop` — усі місця, де з'являється `status`. Для цього `applyNotification` і `syncAgents` отримують аргумент `now`.
- Нова чиста функція `sweep(board, now, view, graceMs)` прибирає кожну завершену задачу, у якої `endedAt + graceMs <= now` і `id !== view`. `graceMs = DROP_COMPLETED_MS = 10000` однаково для `completed`, `failed`, `killed`, `expired`.
- `poll` (раз на `POLL_MS`) викликає `syncAgentStatus`, `expireTasks` і `sweep`. Якщо `tasks` порожній і `view` не задано, він закриває панель (`$.ui.close`), чистить `lines` і зупиняє таймер. Таймер працює, поки `tasks` непорожній або `view` задано; `session.start` запускає його, якщо `tasks` непорожній (замість теперішнього прибирання `completed` при старті). Окремі `$.clock.after(…, dropIfStill)` і `dropIfStill` прибираються.
- Нова задача під час паузи робить `pick` новим (вона працює і найновіша), а закриття не настає, бо `tasks` непорожній.
- Агент, відкритий унизу, не прибирається і не закриває панель, поки він у `view`. Коли повертаєтесь на `main`, наступний `poll` прибирає його, якщо пауза минула.
- `✕` вручну (`ui.close` з origin `person`) як і зараз ставить `dismissed`. Панель лишається закритою до `/console-log`.

### 3.4 Вигляд

Рядок вкладок і рамка `BACKGROUND` прибираються. Лишається одна рамка на всю висоту:

```
╭─ TRANSCRIPT ─────────────────── running · 3 running ─╮
│ ◐ general-purpose·Verify shadow filter…   1m02s · in view │
│ → Bash: cd /home/pc/…                                  │
│ …                                                      │
╰─ general-purpose: Verify shadow filter integrity ──────╯
```

- Заголовок `TRANSCRIPT` для агента, `OUTPUT` для процесу.
- Праворуч: `statusText(task)`, потім ` · transcript unavailable` / ` · file unavailable` при `readFailed`, потім ` · N running`, де N — кількість задач без `status`.
- Перший рядок тіла: `mark(task).glyph`, мітка задачі (`task.label ?? task.command`, обрізана `fit` до ширини), `age(task.startedAt, now)`, а коли задача прийшла з `view`, ще й ` · in view`. Для синтетичного агента вік не показується.
- Далі `R - 3` рядків output (`R = max(8, e.props.scroll.bodyRows)`, як і зараз) (`lines` або `output file not found`), нижня рамка з `task.command`.
- Без задачі (лише `/console-log` на порожньому списку): одна рамка `OUTPUT` з `No background tasks yet.`.

### 3.5 Що прибирається

- `register.tsx`: хук `ui.focus`, `exit`, `leave`, `dropIfStill`, `readCtrlArrows`, атом `hasCtrlArrows`, `Button` і `autoFocus`.
- `layout.ts`: `tabWidth`, `tabWindow`, `paneHint`, `LABEL_MAX`, `tabLabel`.
- `tasks.ts`: `selectTask`, логіка `viewed`.
- `types/index.d.ts`: `Board.selected`, `ConsoleTask.viewed`, стан `selected` і `hasCtrlArrows`. Додаються `endedAt` і стан `view: string | undefined`.
- README (EN і UK): розділ «Keys» і пункти Behaviour про вкладки та `✗`/`■`, що висять до перегляду. Натомість — опис автослідування, закриття через 10 с, `in view` і межі з §2.
- `.claude-plugin/plugin.json`: `version` `0.2.1` → `0.3.0`.

## 4. Out of scope

- Утримання основного вікна на батьківській сесії при перемиканні внизу (§2).
- Ручний вибір процесу: процеси видно лише в автослідуванні.
- Реакція на перемикання внизу, поки панель закрита.
- Вкладки для workflow-агентів і teammates (як і раніше; синтетичний агент у §3.1 лише показує транскрипт).
- Прокрутка output.

## 5. Trade-offs accepted

- Відкриваючи агента внизу, людина бачить його двічі: в основному вікні (так поводиться рушій) і стисло в панелі.
- Процес, старіший за найновішу працюючу задачу, в панелі не побачиш: лише в діалозі рушія внизу.
- `✗` закривається через 10 с так само, як `✓`, і помилка може пролетіти непоміченою. Зате панель завжди закривається сама, коли все скінчилось.
- Прибирання `ctrl+→`/`ctrl+←` ламає тим, хто вписав їх у `keybindings.json`, лише ці прив'язки. Вони стають no-op, бо фокусувати в панелі більше нічого.

## 6. Verification

- `claude plugin test .`:
  - `hooks/tasks.test.ts`:
    - `pick`: найновіша працююча перемагає старішу; працююча перемагає новішу завершену; без працюючих — остання завершена; `view` має пріоритет над працюючими; `view` невідомого агента → синтетичний агент; порожній список → `undefined`;
    - `sweep`: прибирає після `graceMs`, не раніше; не чіпає працюючі; не чіпає задачу з `id === view`;
    - `applyNotification`/`syncAgents`/`expireTasks` ставлять `endedAt`.
  - `hooks/pane.test.tsx`:
    - два старти → тіло показує output другого, рядків вкладок і `BACKGROUND` немає;
    - другий завершився → показ переходить на перший;
    - усе завершилось + 10 с → панель закрита;
    - рендер із `view: { agentId }` → `TRANSCRIPT` і `in view` з транскриптом цього агента навіть після його завершення і 10 с;
    - рендер із `view: {}` → автослідування й закриття.
  - Тести, що спираються на вкладки, `ctrl`-навігацію та `viewed`, переписуються або видаляються.
- `npx -y -p typescript tsc -p . --noEmit` без помилок; `claude plugin validate .` проходить.
- Смоук у живому Claude Code:
  1. Запустити два фонові `general-purpose` агенти з інтервалом і фоновий `sleep 20; echo done`. Панель показує найновіший.
  2. Внизу відкрити старший агент. Панель показує `in view` і його транскрипт.
  3. Повернутись на `main`. Панель знову показує найновіший працюючий.
  4. Дочекатися завершення всього. Через ~10 с панель закривається сама.
